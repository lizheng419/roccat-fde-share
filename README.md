# roccat-fde-share

Grok Bot 和 dot 的内容协作仓库。

## 分工
- **Grok Bot**：负责 X/Twitter 和网页调研、素材整理，默认担任正文主笔，从初稿到终稿统一整合修改，并复审配图。
- **dot**：基于已记录的调研结果审阅结构、语气和事实一致性，提供具体修改意见或通过结论，生成配图，并复审主笔整合后的稿件。
- **ROCCAT**：决定最终版本、配图及是否发布。

## 文件
- `research/`：独立调研文档，记录具体来源链接、观察时间、可核实的信息及限制。
- `drafts/`：各期正文（`epXX.md`）和对应的修改说明、审阅意见（`epXX_notes.md`）。
- `assets/`：配图及说明、审图记录。
- `REVIEW.md`：版本对应的审阅结论。
- `DECISIONS.md`：影响后续工作的正式决定。

## 协作流程
1. Grok Bot 先将调研结果提交到 `research/`，附来源和时间，再将稿件提交到 `drafts/`。
2. 每轮明确一位正文主笔，默认由 Grok Bot 负责。dot 在独立审阅记录中给出具体替换建议或通过结论，不同时重写正文；交接时注明文件路径和提交或文件版本。
3. Grok Bot 整合意见形成候选终稿，dot 复审该版本；dot 生成配图后，由 Grok Bot 实际查看并复审。需要更换主笔时先明确交接，避免两份终稿并行。
4. 改动前先读取最新版本；本地 Git 使用 `git pull --rebase`。一次提交只处理一件事，写清修改内容。
5. 提交前核对并发更新，发生冲突先检查差异，不覆盖对方修改、不强推。修改后重新读取确认。
6. 双方针对同一版本完成审阅后，交给 ROCCAT 决定。

## 约束
- X/Twitter 调研由 Grok Bot 负责，dot 不重复开展同一项调研。证据不足时提出待补问题，不代写调研结论。
- 不把推测当事实，不把未查看的来源或图片记为已核验。
- 未经 ROCCAT 明确批准，不向 X 或其他平台发布任何内容。
- 本 README 只写协作约定，不放口述更正、聊天记录或拼写说明。
